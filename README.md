# 포코노트 - 음악 레슨 에이전트

피아노 선생님의 레슨 기록을 돕는 보안 음성 에이전트입니다. 선생님이 레슨을 녹음하면 음성을 전사하고, 레슨에서 실제로 언급된 내용만 요약해 구조화된 레슨 일지 초안을 만듭니다. 선생님이 초안을 검토하고 승인한 뒤에만 포코노트 수업 기록으로 연결하는 흐름을 목표로 합니다.

이 저장소의 구현은 NVIDIA 해커톤 제출을 위한 독립 데모입니다. 포코노트 전체 서비스의 회원·학생·결제·실제 데이터베이스 백엔드를 대체하지 않습니다.

## 해커톤 문제 정의와 구현 의도

이 프로젝트는 레슨 중 메모를 남기느라 수업의 흐름이 끊기는 피아노 선생님을 위한 **레슨 기록 에이전트**입니다. 선생님은 녹음만 시작하고, 수업이 끝난 뒤 AI가 전사 내용을 레슨 기록 형식으로 정리합니다. 단순한 음성 요약이 아니라 다음 레슨에 바로 사용할 수 있는 구조화된 초안을 만들고, 선생님이 확인·수정·승인하는 과정을 제품의 핵심으로 두었습니다.

대화에서 확인한 NVIDIA 해커톤의 목적과 심사 관점을 이 데모에는 다음처럼 반영했습니다. 이는 공식 심사표의 원문을 대신하는 주장이 아니라, 우리가 확인한 요구사항을 제품 흐름으로 번역한 구현 기준입니다.

| 해커톤 관점 | 레슨AI에서의 구현 |
| --- | --- |
| 실제 문제 해결 | 레슨 중 필기 부담을 줄이고, 수업이 끝난 뒤 바로 검토할 수 있는 레슨 일지를 생성합니다. |
| 에이전트형 흐름 | 녹음 → 전사 → 핵심 추출 → 이전 레슨 비교 → 초안 검토 → 수정/재분석 → 승인/저장의 단계가 연결됩니다. |
| NVIDIA 기술 활용 | Speech NIM을 음성 전사 단계에, Nemotron 계열 모델을 전사 내용의 구조화·분석 단계에 연결할 수 있는 서버 어댑터 경계를 둡니다. |
| 안전성과 신뢰성 | API 키는 서버에만 두고, OpenShell의 네트워크 기본 차단·allowlist·임시 음성 보관·사람의 최종 승인 흐름을 전제로 합니다. |
| 근거 기반 결과 | 녹음에서 확인되지 않은 곡·구간·강점·과제는 임의로 채우지 않고 비워 둡니다. 이전 레슨 비교도 전달된 문맥이 있을 때만 수행합니다. |
| 사용자 중심 UX | 녹음 중지 확인, 분석 로딩, 편집 가능한 초안, 음성 보정 후 재분석, 저장 확인 모달을 포함해 결과를 검토할 수 있게 했습니다. |
| 구현 가능성과 확장성 | 브라우저 데모와 실제 NVIDIA/백엔드 호출을 어댑터로 분리해, 해커톤 데모에서 운영 서비스로 확장할 수 있게 했습니다. |

### 심사 시 보여줄 핵심 시나리오

1. 레슨 기록 화면에서 `레슨 AI로 요약하기`를 선택합니다.
2. 녹음을 시작하고, 종료 확인 후 분석을 진행합니다.
3. 음성에서 추출된 내용을 오늘의 요약·곡/구간·잘한 점·개선할 점·다음 연습 과제로 확인합니다.
4. 지난 레슨 문맥이 있으면 변화와 반복 이슈를 비교합니다.
5. 선생님이 초안을 수정하거나 `음성 보정 후 다시 분석`을 실행합니다.
6. 저장을 승인하면 해당 회차의 레슨 기록으로 돌아갑니다.

이 시나리오는 모델이 답을 한 번 출력하는 데모가 아니라, NVIDIA 음성·언어 모델을 실제 교사의 업무 흐름 안에 배치하고 사람이 결과를 통제하는 에이전트 제품을 보여주는 데 목적이 있습니다.

## 현재 구현된 기능

### 1. 레슨 에이전트 화면

포코노트 SPA 안에 `포코노트 - 레슨 에이전트` 화면을 추가했습니다.

- 레슨 대상 학생과 수업 날짜를 기준으로 세션 시작
- 녹음 중 경과 시간 표시
- 녹음 종료 후 전사와 분석 상태 표시
- 생성된 레슨 일지 초안 검토 및 수정
- 초안 승인 또는 폐기
- 승인된 초안을 포코노트 수업 기록 형태로 변환

### 2. 두 가지 실행 모드

기본값은 서버와 API 비용이 발생하지 않는 데모 모드입니다.

| 모드 | 동작 | 용도 |
| --- | --- | --- |
| Demo | 샘플 녹음·전사·분석 결과를 사용 | 서버 없이 화면 흐름 시연 |
| NVIDIA 연결 모드 | 브라우저 녹음 → 서버 → Speech NIM → Nemotron | 별도 서버를 추가했을 때의 연결 경로 |

현재 이 폴더에서 바로 실행되는 것은 Demo 모드입니다. NVIDIA 모드는 `lesson-agent.js`에 어댑터와 요청 계약이 준비되어 있지만, 실제 API 서버와 GPU 엔드포인트는 이 독립 데모 폴더에 포함하지 않았습니다.

실제 NVIDIA 모드에서는 브라우저에 API 키를 넣지 않습니다. 브라우저는 우리 서버의 API만 호출하고, 서버가 Speech NIM과 Nemotron 호환 엔드포인트를 호출해야 합니다.

### 3. 레슨 일지 구조화

분석 결과는 다음 필드로 관리합니다.

- 레슨 요약
- 곡명과 레슨에서 언급된 구간
- 잘한 점
- 개선할 점
- 이전 레슨 이후의 변화
- 반복해서 나타난 이슈
- 다음 연습 과제
- 다음 레슨에서 확인할 항목

음성에서 확인되지 않은 내용은 모델이 임의로 채우지 않고 빈 값으로 둡니다. 곡명이나 구간도 실제 발화에 근거가 있을 때만 기록합니다.

이전 레슨 정보가 전달되면 다음 레슨에서 이어지는 곡이나 과제인지 비교할 수 있습니다. 다만 이전 레슨에 대한 명시적인 근거가 없으면 이어서 진행한다고 단정하지 않습니다.

### 4. 재분석 시에만 음성 보정

첫 분석은 원본 녹음을 바로 Speech NIM으로 전사합니다. 결과가 좋지 않을 때 선생님이 `음성 보정 후 다시 분석`을 누른 경우에만 선택적 전처리 단계를 거칩니다.

```text
첫 분석
브라우저 녹음
  → Speech NIM 전사
  → Nemotron 레슨 일지 분석

재분석 요청 시
브라우저에 임시 보관된 녹음
  → NVIDIA Maxine/BNR 호환 전처리 서버
  → Speech NIM 재전사
  → Nemotron 재분석
```

현재 코드에는 전처리 서버를 연결할 수 있는 어댑터와 설정 지점이 있습니다. 실제 Maxine/BNR GPU 서비스를 켜지 않으면 전처리는 실행되지 않습니다. VAD 역시 Speech NIM 배포 프로파일에서 활성화하는 연결 지점만 준비되어 있습니다.

### 5. 임시 음성 보관과 삭제

재분석을 위해 원본 음성은 브라우저 메모리에 임시 보관할 수 있습니다.

- 분석 후 검토 중에만 임시 보관
- 승인 또는 폐기하면 즉시 삭제
- 최대 1시간이 지나면 자동 삭제
- 브라우저 `localStorage`나 장기 저장소에는 저장하지 않음

실제 서버를 추가하는 경우 녹음 중 30초 단위 OPUS 청크를 서버에 임시 업로드하고, 서버가 순서대로 조립한 뒤 Speech NIM에 전달하는 구조로 확장할 수 있습니다. 현재 데모 모드에서는 네트워크 업로드가 발생하지 않습니다.

## 전체 동작 흐름

```text
1. 선생님이 레슨 에이전트 시작
2. 브라우저 MediaRecorder가 레슨 음성을 녹음
3. 실제 연결 모드에서는 녹음 중 30초 청크를 서버에 임시 업로드
4. 녹음 종료 후 서버가 청크를 순서대로 조립
5. Speech NIM이 조립된 음성을 텍스트로 전사
6. 전사 텍스트와 최소한의 수업 문맥을 Nemotron에 전달
7. 구조화된 레슨 일지 초안 생성
8. 선생님이 내용을 검토·수정
9. 필요하면 음성 보정 후 재분석
10. 선생님이 승인
11. 승인된 초안을 포코노트 수업 기록으로 변환하고 저장 API에 전달
```

Nemotron에는 원본 음성 파일을 직접 보내지 않습니다. 음성 처리는 Speech NIM의 전사 단계에서 끝내고, Nemotron에는 전사 텍스트와 학생의 불투명 식별자(UUID 등), 날짜, 이전 레슨 문맥만 전달합니다. 학생 이름은 모델 요청에 포함하지 않는 구조입니다.

## NVIDIA 기술 구성

- NVIDIA Speech NIM
  - 음성에서 텍스트로 변환하는 ASR 단계
  - 현재 서버 어댑터는 `/v1/audio/transcriptions` HTTP 계약을 사용
  - 한국어 전사를 포함하는 Whisper Large V3 프로파일을 기본 예시로 사용
- NVIDIA Nemotron 호환 Chat Completions 엔드포인트
  - 전사 텍스트를 레슨 일지 JSON으로 구조화
  - 곡·구간·강점·개선점·연습 과제 등을 근거 기반으로 추출
- OpenShell / NemoClaw
  - 에이전트가 외부 모델과 도구를 호출하는 보안 경계로 연결할 수 있는 구조
  - API 키를 브라우저가 아닌 서버 또는 보안 게이트웨이에 보관
- NVIDIA Maxine / BNR 연결 지점
  - 재분석을 요청한 경우에만 음성 보정에 사용할 수 있는 선택 단계
- VAD
  - 음성 구간 검출을 위한 선택 기능
  - 실제 동작은 Speech NIM 배포 프로파일에서 활성화한 뒤 검증 필요
- 브라우저 `MediaRecorder` API
  - 해커톤 데모의 음성 입력
- Node.js HTTP 서버
  - 전사·분석 API와 NVIDIA 엔드포인트 사이의 서버 측 어댑터

## 실행 방법

### 서버 없는 데모 모드

Node.js가 설치된 환경에서 정적 서버를 실행합니다.

```bash
npx -y serve . -l 4173
```

브라우저에서 다음 주소를 엽니다.

```text
http://localhost:4173/poconote-app.html#/students/doyoon/lessons/record/8
```

기본 데모 모드는 마이크 권한, NVIDIA 계정, API 키, GPU 서버 없이 다음 흐름을 재현합니다.

```text
레슨 에이전트 시작 → 녹음 종료 → 샘플 전사 → 일지 생성 → 검토 → 승인
```

### NVIDIA 실행 모드

NVIDIA 서버 연동을 추가할 때는 환경변수를 서버에만 설정합니다. 현재 이 폴더에는 화면 데모용 클라이언트만 포함되어 있습니다.

```bash
추가 예정: `node scripts/check-lesson-agent-config.mjs` 및 `node server/lesson-agent-api.mjs`
```

상세한 Speech NIM, Nemotron, OpenShell/NemoClaw 연결 문서는 서버 코드를 분리해 추가할 때 함께 이동합니다.

실제 모드를 선택하려면 페이지가 로드되기 전에 다음 설정을 사용합니다.

```js
window.LESSON_AGENT_MODE = 'nvidia';
```

API 키는 반드시 서버 환경변수에만 두어야 합니다. 키를 HTML, 브라우저 JavaScript, GitHub 저장소에 넣지 마세요.

### 서버 저장 API 연결 계획

서버 저장 API는 만들 수 있습니다. 다만 현재 폴더에는 운영 서버가 없으므로 `저장하기`는 데모 상태를 갱신하고 해당 회차 화면으로 돌아가는 동작까지만 담당합니다. 다음 계약으로 별도 API를 추가하면 승인된 레슨 일지를 DB에 저장할 수 있습니다.

```http
POST /api/lesson-records/:lessonId/approved
Content-Type: application/json
Authorization: Bearer <teacher-session>

{
  "studentUuid": "opaque-student-id",
  "lessonId": "8",
  "record": {
    "summary": "...",
    "songSection": "...",
    "strengths": "...",
    "improvements": "...",
    "nextPractice": "..."
  }
}
```

운영 API에서는 브라우저가 보낸 학생 식별자와 회차를 그대로 신뢰하지 않고, 로그인 세션의 선생님·스튜디오 권한으로 접근 범위를 다시 확인해야 합니다. 기존 서비스의 DB 트랜잭션과 중복 요청 방지 키를 사용하는 것을 권장합니다.

기존 포코노트의 인증·학생 조회·DB 저장 코드는 메인 서비스에 남겨 두고, 이 해커톤 폴더에는 복사하지 않았습니다. 서버를 추가할 때는 `lesson-agent.js`의 원격 분석 어댑터와 같은 경계에 `LessonRepository` 구현을 연결하면 됩니다.

### OpenShell 정책 템플릿

OpenShell/NemoClaw 정책 템플릿과 서버 API 구현은 현재 폴더에 포함하지 않았습니다. 실제 서버를 추가할 때 네트워크 기본 차단과 NVIDIA 엔드포인트 allowlist를 함께 추가해야 합니다.
